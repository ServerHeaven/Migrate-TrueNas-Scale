Migrar TrueNAS
de USB a USB

Cómo reemplazar el dispositivo de arranque de TrueNAS (USB, DOM o SSD pequeño) por uno nuevo, manteniendo todas tus pools ZFS, datasets, shares, usuarios y configuración intactos.

¿Cómo funciona esto?
Entender la arquitectura antes de tocar nada

TrueNAS separa completamente el sistema operativo (instalado en el USB/DOM/SSD de arranque) de los datos (almacenados en las pools ZFS sobre los discos de datos). Esto significa que puedes reemplazar el dispositivo de arranque sin tocar tus datos en absoluto.

┌─────────────────────────────────────────────────────────┐ │ SERVIDOR TRUENAS │ │ │ │ [USB de arranque] ←── Sistema operativo TrueNAS │ │ OS + Config + DB ←── Configuración (exportable) │ │ │ │ [Disco 1] [Disco 2] ←── Pool ZFS "tank" │ │ [Disco 3] [Disco 4] ←── Pool ZFS "backup" │ │ │ │ Las pools ZFS son INDEPENDIENTES del USB de arranque │ └─────────────────────────────────────────────────────────┘
✓ Tranquilidad
Tus datos en las pools ZFS no se tocan en ningún momento. ZFS guarda todos los metadatos de la pool en los propios discos de datos, no en el USB de arranque.

El proceso en resumen

  1. Exportar el backup de configuración de TrueNAS (archivo .tar)
  2. Anotar nombres de pools y estado actual
  3. Apagar, retirar USB viejo, insertar USB nuevo
  4. Instalar TrueNAS limpio en el USB nuevo
  5. Importar las pools ZFS existentes
  6. Restaurar el backup de configuración
  7. Verificar que todo funciona
Requisitos previos
Lo que necesitas tener antes de empezar

Material físico

  • USB nuevo (mínimo 16 GB, recomendado 32 GB+, preferiblemente industrial/SLC)
  • Otro USB o PC para crear el instalador de TrueNAS
  • Acceso físico al servidor (o IPMI/iDRAC)

Software

  • Balena Etcher o Rufus para crear el USB instalador
  • ISO de TrueNAS SCALE o CORE — misma versión que tienes instalada (o más nueva)
  • Acceso a la WebUI de TrueNAS antes del proceso
⚠ Versión del instalador
Usa la misma versión de TrueNAS que tenías instalada, o una más nueva. Nunca instales una versión más antigua, ya que las pools ZFS creadas con versiones superiores pueden no ser importables.
✗ NUNCA hagas esto
  • × No insertes el USB nuevo con el servidor encendido (a menos que sea hot-plug confirmado)
  • × No formatees ni toques los discos de datos
  • × No saltes el paso del backup de configuración
01
Exportar backup de configuración
El archivo más importante de todo el proceso

Desde la WebUI de TrueNAS, exporta la configuración completa del sistema. Este archivo contiene usuarios, grupos, shares SMB/NFS, tareas, datasets, credenciales y toda la configuración del sistema operativo (pero no los datos en sí).

En TrueNAS SCALE

  1. Ve a System → General Settings
  2. Haz clic en Manage Configuration
  3. Selecciona Download File
  4. Activa la opción Export Password Secret Seed (importante para credenciales cifradas)
  5. Descarga el archivo .tar y guárdalo en un lugar seguro (no en las pools)

En TrueNAS CORE

  1. Ve a System → General
  2. Haz clic en Save Config
  3. Marca Export Password Secret Seed
  4. Guarda el archivo .db resultante
⚠ Password Secret Seed
Si no exportas el Secret Seed, las contraseñas de servicios como rsync, las claves de cifrado de pools y otros secretos no podrán restaurarse. Siempre actívalo.

Verificación del backup

Comprueba que el archivo se descargó correctamente y tiene un tamaño razonable (no 0 bytes):

# En Linux/Mac — verificar que el archivo existe y no está vacío
ls -lh truenas-SCALE-*.tar

# Debería mostrar algo como:
-rw-r--r-- 1 pedro pedro 142K Mar 15 19:44 truenas-SCALE-24.10-backup.tar
02
Anotar pools y estado de discos
Información crítica para la importación posterior

Antes de apagar, recoge información sobre tus pools. Aunque ZFS puede re-descubrir las pools automáticamente, es útil tener esta información a mano.

Desde la WebUI

  1. Ve a Storage y anota el nombre de cada pool (ej: tank, data, backup)
  2. Confirma que todas las pools están en estado ONLINE
  3. Haz una captura de pantalla de la vista de discos si quieres referencia visual

Desde la consola / SSH

# Ver todas las pools y su estado
zpool list

# Ver estado detallado con discos
zpool status

# Exportar la info completa a un archivo (copia esto también al backup)
zpool status -v > /tmp/pools_backup.txt
zpool list -v >> /tmp/pools_backup.txt
cat /tmp/pools_backup.txt

La salida te mostrará algo así:

NAME     SIZE   ALLOC  FREE   FRAG  EXPANDSZ  HEALTH  ALTROOT
tank     7.27T  4.12T  3.15T    4%         -  ONLINE  -
backup   3.63T  1.20T  2.43T    2%         -  ONLINE  -

# Y con zpool status:
  pool: tank
 state: ONLINE
  scan: scrub repaired 0B in 02:14:33 with 0 errors
config:
        NAME        STATE     READ WRITE CKSUM
        tank        ONLINE       0     0     0
          mirror-0  ONLINE       0     0     0
            sda     ONLINE       0     0     0
            sdb     ONLINE       0     0     0
ℹ️ GUID de pools
ZFS identifica las pools por GUID (identificador único), no por nombre del disco. Por eso una pool puede importarse aunque los discos cambien de nombre de sda a sdb.
03
Apagar el sistema correctamente
Shutdown limpio para proteger la integridad ZFS

Es importante hacer un apagado limpio para que ZFS haga checkpoint y cierre las pools correctamente.

Desde WebUI

  1. Ve a la esquina superior derecha → botón de encendido
  2. Selecciona Shut Down
  3. Confirma y espera a que el sistema se apague completamente

Desde consola / SSH

sudo shutdown -h now
✗ No desenchufes sin apagar
Forzar el apagado puede dejar las pools ZFS en estado "dirty". Aunque ZFS tiene journaling y se recupera, es mejor no arriesgarse.

Una vez apagado, extrae el USB viejo de su slot. Guárdalo por si necesitas volver atrás. Inserta el USB nuevo en el mismo puerto.

04
Instalar TrueNAS en el USB nuevo
Instalación limpia — igual que la primera vez

Crear el USB instalador

Necesitas un segundo USB temporal que actuará de instalador. Lo usarás solo durante la instalación y luego puedes reutilizarlo. El método recomendado es Balena Etcher por su simplicidad y fiabilidad en cualquier sistema operativo.

Paso 1 — Descargar la ISO de TrueNAS

  1. Ve a https://www.truenas.com/download-truenas-scale/ (o /truenas-core/ si usas CORE)
  2. Descarga la misma versión que tenías instalada — o una más nueva. El archivo tendrá un nombre como TrueNAS-SCALE-24.10.2.iso
  3. Opcionalmente, verifica el checksum SHA256 para confirmar que la descarga es íntegra: 
    # Windows (PowerShell)
Get-FileHash TrueNAS-SCALE-24.10.2.iso -Algorithm SHA256

# Linux / Mac
sha256sum TrueNAS-SCALE-24.10.2.iso
    Compara el resultado con el hash publicado en la página de descargas de TrueNAS.

Paso 2 — Descargar e instalar Balena Etcher

  1. Ve a https://etcher.balena.io
  2. Descarga la versión para tu OS (Windows Installer, macOS DMG, o Linux AppImage)
  3. Instala y abre Balena Etcher

Paso 3 — Grabar la ISO en el USB instalador

Usa un USB de al menos 8 GB para el instalador. No uses el USB nuevo de destino — ese es donde instalarás TrueNAS después.

Proceso de instalación

  1. Conecta el USB instalador y el USB destino (nuevo) al servidor
  2. Arranca desde el USB instalador (F11/F12/DEL en BIOS para el boot menu)
  3. Espera a que cargue el instalador de TrueNAS
  4. Selecciona Install/Upgrade
  5. Cuando pregunte dónde instalar, selecciona el USB nuevo.
    ✗ CRÍTICO — Selección del destino
    Asegúrate de seleccionar el USB nuevo y NO los discos de datos. Compara los tamaños: tu USB nuevo (16-32 GB) vs tus discos de datos (TB). El instalador sobreescribe el destino por completo.
  6. Establece la contraseña de root cuando se pida
  7. Cuando termine, selecciona Reboot
  8. Retira el USB instalador antes de que arranque

Primera vez que arranca

TrueNAS arrancará en un sistema limpio. Verás la IP asignada por DHCP en la consola. Accede a la WebUI con esa IP desde un navegador. 

# La consola mostrará algo así:
The web interface is at:
  http://192.168.1.100
05
Importar las pools ZFS
Reconectar tus datos al nuevo sistema

Este es el paso más importante. TrueNAS instalado de cero no conoce tus pools, pero ZFS puede descubrirlas automáticamente leyendo los metadatos en los propios discos.

Método 1: Desde la WebUI (recomendado)

  1. Accede a la WebUI del TrueNAS recién instalado
  2. Ve a Storage → Import Pool
  3. TrueNAS escaneará los discos y mostrará las pools disponibles
  4. Selecciona cada pool que quieras importar
  5. Si las pools estaban cifradas, se te pedirá la passphrase o el keyfile
  6. Haz clic en Import y espera a que complete
  7. Repite para cada pool adicional

Método 2: Desde consola (alternativo)

Si la WebUI no detecta las pools o prefieres la consola:

# Buscar pools importables (no las importa aún)
zpool import

# La salida mostrará las pools disponibles:
   pool: tank
     id: 12345678901234567
  state: ONLINE
 action: Online the device using 'zpool online' or replace the device with 'zpool replace'.
 config:
        tank        ONLINE
          mirror-0  ONLINE
            sda     ONLINE
            sdb     ONLINE

# Importar una pool específica
zpool import tank

# Importar todas las pools encontradas de una vez
zpool import -a

# Si la pool tiene un nombre diferente o hay conflicto, importar por GUID
zpool import -d /dev 12345678901234567 tank

# Para pools cifradas con encryption key
zpool import -l tank
ℹ️ Estado EXPORTED vs ONLINE
Cuando TrueNAS se apaga correctamente, exporta las pools (estado EXPORTED). Si el apagado fue forzado, pueden aparecer como ONLINE con el aviso "pool was previously in use". Puedes importarlas igualmente con zpool import -f tank.

Verificar importación

# Verificar que las pools se importaron correctamente
zpool status
zpool list

# Verificar datasets
zfs list

# Todo debería estar ONLINE
NAME     SIZE   ALLOC  FREE   FRAG  EXPANDSZ  HEALTH  ALTROOT
tank     7.27T  4.12T  3.15T    4%         -  ONLINE  -
06
Restaurar la configuración
Volver a tener todos tus shares, usuarios y servicios

Con las pools importadas, ahora restauramos la configuración del sistema (usuarios, SMB/NFS shares, tareas cron, etc.) desde el backup del paso 1.

En TrueNAS SCALE

  1. Ve a System → General Settings → Manage Configuration
  2. Haz clic en Upload File
  3. Selecciona el archivo .tar que descargaste en el paso 1
  4. El sistema aplicará la configuración y se reiniciará automáticamente
  5. Espera a que vuelva a estar disponible (1-3 minutos)

En TrueNAS CORE

  1. Ve a System → General
  2. Haz clic en Upload Config
  3. Selecciona el archivo .db del backup
  4. Confirma y espera el reinicio
⚠ Orden importa
Importa las pools ANTES de restaurar la configuración. Si restauras la config primero, TrueNAS intentará montar datasets que aún no existen y pueden aparecer errores que se resuelven solos al importar después, pero es más limpio en el orden correcto.

Ejecutar un scrub de verificación

Como buena práctica, lanza un scrub para verificar la integridad de los datos:

# Desde consola
zpool scrub tank

# Ver progreso
zpool status tank

# O desde WebUI: Data Protection → Scrub Tasks → RUN NOW
✓ ¡Migración completada!
Si todas las verificaciones son correctas, la migración fue exitosa. Guarda el USB viejo en un cajón durante unas semanas por si acaso, luego puedes formatearlo o reutilizarlo como instalador.
Problemas comunes y soluciones
Cuando las cosas no van según el plan

❌ La pool no aparece en el scan de importación

# Forzar búsqueda en todos los dispositivos
zpool import -d /dev

# Si los discos usan rutas /dev/disk/by-id (más estable)
zpool import -d /dev/disk/by-id

# Ver todos los discos reconocidos
lsblk
fdisk -l

❌ Error "pool was previously in use"

# Importar forzando (safe si estás seguro de que el sistema anterior está apagado)
zpool import -f tank

❌ Pool en estado DEGRADED tras importar

# Ver qué disco falta
zpool status tank

# Si el disco está presente pero con nombre diferente
zpool online tank /dev/sdc

# Lanzar scrub para verificar
zpool scrub tank

❌ Los shares SMB no son accesibles tras restaurar config

  • Verifica que el servicio SMB está activo en System → Services
  • Comprueba que los datasets tienen los permisos ACL correctos
  • Reinicia el servicio SMB desde la WebUI
  • Comprueba el firewall si tienes uno

❌ TrueNAS arranca en modo de mantenimiento

# Desde la consola, importar pools manualmente
zpool import -a -f

# Reiniciar servicios
service middlewared restart

❌ Apps de TrueNAS SCALE no funcionan

Las apps (ix-applications) son complejas de migrar. Si tenías apps de Kubernetes, necesitarás reinstalarlas. Los datos de las apps suelen estar en un dataset ix-applications que puedes volver a asignar como directorio de apps desde Apps → Settings → Choose Pool.

Tips y recomendaciones
Para que esto no vuelva a ser un drama

🔵 Usa un SSD pequeño en lugar de USB

Los USB convencionales tienen una vida útil limitada en escrituras. Para el boot de TrueNAS considera un SSD M.2 SATA barato (60-120 GB), un DOM (Disk on Module) industrial, o incluso un SSD de 2.5" dedicado. Más fiable y más rápido.

🔵 Boot Mirror: dos USBs en espejo

TrueNAS permite instalar en dos USBs en modo mirror. Si uno falla, el otro sigue funcionando sin intervención. Ve a System → Boot Pool Status → Attach para añadir un segundo dispositivo al mirror de arranque.

🔵 Automatiza el backup de configuración

Configura un script que exporte la configuración periódicamente a una pool o ubicación externa. En TrueNAS SCALE puedes usar un script en System → Advanced → Init/Shutdown Scripts. 

#!/bin/bash
# Script de backup automático de config TrueNAS
DEST="/mnt/tank/backups/truenas-config"
DATE=$(date +%Y%m%d_%H%M)
mkdir -p $DEST
# TrueNAS SCALE guarda el config en:
cp /data/freenas-v1.db $DEST/config_$DATE.db
cp /data/pwenc_secret $DEST/secret_$DATE
# Mantener solo los últimos 10 backups
ls -t $DEST/config_*.db | tail -n +11 | xargs rm -f

🔵 Documenta tus pools y discos

Guarda en algún lugar (papel, wiki, etc.) el mapeo de tus discos: número de serie → slot físico → nombre en pool. Cuando un disco falle a las 2 AM, lo agradecerás.

✓ Resumen del proceso
Backup config → Apuntar pools → Apagar → Cambiar USB → Instalar TrueNAS → Importar pools → Restaurar config → Verificar. El proceso completo suele llevar entre 30 y 60 minutos dependiendo del hardware.
